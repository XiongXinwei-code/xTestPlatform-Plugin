# 更新记录

## v1.2.7 - 2026-09-01
- 修复：NI-XNET `nxReadFrame` 的托管接收缓冲区显式标记为输出方向，确保原生驱动写入的 0x70C 等接收帧能够复制回 .NET 缓冲区。
- 优化：NI-XNET 接收改用单个最大 Raw Frame 大小的缓冲区，降低大缓冲区“等待填满”语义对单帧 UDS 响应轮询的影响。
- 优化：UDS 超时不再伪装成 ECU 返回的 `NRC 0x10`；步骤结果会显示 NI-XNET 返回字节数、解析帧数、过滤帧数和实际看到的 CAN ID，便于区分驱动接收、ID 配置与物理总线问题。

## v1.2.3 - 2026-09-01
- 修复：序列已将“擦除携带地址和长度”保存为 false 时，即使启用了映射范围仍发送 `31 01 FF 00` 并收到 `NRC 0x13` 的问题；映射范围模式现在由执行器强制发送 `ALFID + 地址 + 长度`。
- 优化：编辑器在映射范围模式下始终显示带参数擦除为选中状态，避免配置语义与实际报文不一致。

## v1.2.2 - 2026-09-01
- 修复：UDS_Flash“擦除与下载”页缺少“下载前延时”所在的 Grid 行定义，导致底部的擦除参数与下载前延时控件重叠。

## v1.2.1 - 2026-09-01
- 修复：历史 UDS_Flash 序列缺少“擦除携带地址和长度”字段时，反序列化后可能被当作无参数擦除，实际发送 `31 01 FF 00` 并收到 `NRC 0x13` 的问题；未配置该字段现在默认按带参数擦除处理。
- 优化：启用“使用映射范围”时自动选中带参数擦除，与 ZLG 的“带参数擦除”映射下载配置保持一致；用户仍可在擦除与下载页明确切换为无参数擦除。

## v1.2.0 - 2026-09-01
- 新增：UDS_Flash 支持“映射范围”模式，可配置映射起始/结束地址和地址空洞填充字节；擦除、0x34 请求下载、传输与 CRC 将以一个完整连续范围执行，兼容 ZLG 文件下载的映射配置。
- 新增：UDS_Flash 可配置擦除例程是否携带 `ALFID + 地址 + 长度` 参数，支持带参数与无参数两类 ECU 擦除例程。
- 新增：UDS_Flash 支持下载前延时，用于等待 FlashDriver 激活；可配置为 500 ms 以匹配目标 ECU 的 APP 下载流程。
- 优化：单块最大字节数设为 0 时完全采用 ECU 在 0x34 正响应中返回的最大块长度，匹配 ZLG 未启用自定义块大小的行为。
- 优化：启用日志时输出擦除与 0x34 请求的完整 UDS 报文，便于与外部诊断工具抓包逐字节对照。

## v1.1.0 - 2026-08-19
- 优化：内置周立功 ZLGCAN x64 原生库，插件生成时随包发布，使用 ZLG 设备时无需再手工配置 zlgcan.dll 的 PATH 环境变量。
- 修复：插件由宿主动态加载时，zlgcan.dll 因搜索路径指向宿主进程目录而加载失败的问题；现按插件自身目录、宿主插件目录等多个候选位置依次探测。
- 修复：随库内置 VC++ 2013 运行库（msvcr120.dll、msvcp120.dll）。zlgcan.dll 依赖该运行库，而 Windows 不自带，缺失时会被 .NET 报成“找不到 zlgcan.dll”，导致未安装周立功官方驱动的现场机器无法打开通道。
- 优化：ZLG 通道打开失败时输出原生库加载的诊断信息（已定位目录、kerneldlls 是否完整、VC++ 运行库检查、实际加载异常、已探测路径），便于现场排查。
