## 三、分插件功能与行为说明

### 1. CAN：原始 CAN、CANopen、UDS、XCP

**新增六个 CANopen 步骤：**

| StepTypeId | 功能 |
| --- | --- |
| `CANopen.ServiceStart` | 启动持续接收；默认仅接收，可显式开启监测 SYNC |
| `CANopen.CycleStart` | 单任务按顺序发送 RPDO，再发送关联 SYNC；支持实时目标或有限点表 |
| `CANopen.CycleInputsUpdate` | 原子发布下一版完整目标字节，不在后台求值活跃序列表达式 |
| `CANopen.SnapshotRead` | 立即返回最新反馈与服务诊断，不阻塞等待所有 TPDO |
| `CANopen.CycleStop` | 冻结新目标、等待本运动代次发送收尾、执行配置的所有者停机 SDO；可返回监测 |
| `CANopen.ServiceStop` | 结束服务及观察订阅，确认相关工作退出 |

- TPDO/反馈列表为 **1～128 路可配置**，不固定四路。COB-ID、DLC、字节布局及目标值仍由序列决定；每路独立判断时效，不要求同一 SYNC。
- 反馈输出包含原始数据、序号、原始时间/时间域、时钟代次、帧龄上界、有效状态、积压/淘汰及后台故障。未知时间保持未知，不拿出队时刻刷新采集时间。
- 一个连接只有一个 SYNC 调度者；显式纯 SYNC 模式不伪造 RPDO。监测周期和运动目标周期分开配置。
- 支持不可变有限时间点表，按单调时间选择目标；超期报告故障，不密集补发过时点。完整有限轨迹不套用实时目标续期超时；本版不做轨迹规划、单位换算、插值或分块追加。
- 停止按捕获的**运动代次与固定停止结果**确认，不拿继续变化的监测全局发送计数误判本次运动。
- NI-XNET 严格确认核对待确认票据、完整帧/顺序/代次、回显、原生 Write 退出及发送会话完成。ZLG 已核对的 USBCANFD-100U/200U 在驱动接受回显配置后提供对应能力；其他型号不伪报支持。
- NI 原始时钟映射与 ZLG 回显因果锚点分别建立保守采集时间下界。时钟重置/跳变/过期则标记未知，不能强制 Valid。
- 接收/发送任务、nxStop/nxClear、ZLG Reset/Close 及其他厂商部分打开的归属与返回值纳入真实收尾。Kvaser CAN FD 数据段按显式位时序应用采样点；TOSUN 核对 ABI 与库级生命周期，未知外部句柄不强行接管。
- 原始 CAN 与完整 UDS/XCP 事务用同一 owner、实际 I/O 门和单调期限；Open/Close/基础发送/周期停止等待可配置。UDS 新增事务总期限和响应重组大小上限；ISO-TP 流控、短响应、标识位宽、枚举及 Flash 首次擦写前参数校验更严格。
- Flash 编辑分析只解码支持的字面量、后台解析固件、屏蔽过时结果；损坏预设不被空表覆盖，文件错误显式显示。
- **对比澄清：**终端电阻及仲裁/数据段采样点字段在本次云端基线已存在，不把历史已有功能重新统计为本次新增；此处新增的是相应运行可靠性/厂商适配修复和可配置期限。

主要源码：`CAN/CanPlugin/Runtime/`、`CAN/CanPlugin/CANopen/Cyclic/`、`CAN/CanPlugin/Adapters/`、UDS/XCP/Flash 执行器及匹配 UI。详细功能协议见 [CANopen 服务说明](../../CAN/CONTROLLED_CANOPEN.md)，该文件内早期 1.0.33 版本段为阶段记录；当前交付版本以本说明版本表和构建清单为准。

### 2. CiA402：轴会话与运动步骤

- 绑定为无副作用关联，允许只读绑定未被其他会话占用的已使能、QuickStop 或故障态轴；不自动停轴、释能、切模式或恢复旧目标。
- BindAxis 的调用令牌只约束本次初始化，不长期绑定持久会话；修复绑定完成后取消该令牌导致持续“轴会话已终止”。
- 反馈支持可增删的多 TPDO 列表，兼容旧单 TPDO 设置；缺失/过期反馈仍返回 Error，不以旧缓存伪造成功。
- 被动 TPDO 超时只有在原读取实际退出后可重新读取；控制/SDO 或仍未退出的 I/O 继续保留保护，不绕过共享 CAN。
- 停止/解绑/自动回收共用自身清理流程及可配置 `ShutdownTimeoutMs`，同步 Dispose 不再阻塞等待硬件。只管理轴及节点租约，不关闭父 CAN。
- 详细错误记录首终止原因、绑定步骤、会话/连接/节点、期限、阶段、所需/已收/缺失反馈及异常链，方便定位首故障而非只提示重绑。
- 运动步骤实际提交和输出受步骤/通信期限及原运行代次保护；使能和模式切换避免继承旧运动启动位/非零目标。

主要源码：`CiA402/Cia402Plugin/Core/AxisSession.cs`、`AxisController.cs`、`AxisOperationBoundary.cs`、`Executors/ExecutorBase.cs`、`Transport/` 及 BindAxis UI。

### 3. NiDaq：新增 AO 与既有采集/数字任务

- 新增 `NiDaq.AoConfig` / `NiDaq_AO_Config` 与 `NiDaq.AoWriteSingle` / `NiDaq_AO_WriteSingle`，有独立编辑器、图标、描述及校验。
- AO 首版为**电压、按需单点输出**：配置通道/量程/显式初值，使用 TaskStart 后单点写入，复用 TaskStop；不隐式启动、不提供硬件定时波形或电流输出。
- 必须显式选择设备默认停止行为或用户审核的最终值；不默认 0 V 安全，不保证 Stop/Dispose 一定归零。
- 收尾冻结新写入，等待原 writer 实际退出，按策略处理终值，再 Stop/Dispose。成功终值不重复发送；终值是否到达未知时禁止盲目重试。
- AI/CI/同步读取、DI/DO 临时任务在 native 配置前登记执行 owner；中断后同硬件重开等原资源真正释放。同步任务校核采样时钟，导出受独立配置期限约束，过时结果不发布。
- 删除旧 `NiDaqTimeoutHelper.cs` 和 `NiDriverCheck.cs`：前者只结束软等待但未跟踪真实后台任务，后者在执行入口同步枚举设备并永久缓存失败；改为 owner 内的实际 SDK 操作/错误及真实任务管理。

主要源码：`NiDaq/NiDaqPlugin/Helpers/DaqTaskResource.cs`、`DaqTaskFactory.cs`、`DaqPhysicalResources.cs`、`AnalogOutputSession.cs`、`AoOutputPlan.cs` 及新增 AO Setting/Executor/UI。

### 4. OPC UA

- 一个连接资源独占自身 Session、请求、订阅和后台采集；关闭只针对捕获的精确实例，不按名称误删之后新建的会话。
- 建立、采集起停、读取/消费/CSV 导出和关闭等待预算可配置；超时不提前遗忘实际请求/取消回调。
- 采集输出保留质量与时间信息，坏质量不当作条件满足；CSV 按序号确认消费，部分追加失败隔离目标路径，不静默重试重复写入。
- 旧运行迟到的连接创建、日志和输出不能覆盖新运行；订阅 Delete/SessionClose 必要清理不会被普通执行失效围栏挡住。
- **不新增自动重连。** 恢复仍由用户序列决定；没有把客户端修复宣称为所有现场偶发断连的唯一原因。

主要源码：`OpcUa/OpcUaPlugin/Helpers/OpcUaConnectionResource.cs`、采集/消费/CSV helpers、执行器及批读写/采集编辑器。

### 5. LIN

- WriteRead 作为完整事务串行化，避免并发步骤消费彼此应答。
- NI 打开/Wakeup 多阶段复查原取消与总预算；实际未退出保持 owner，安全释放后首次重开可恢复。
- 周期任务具名归属连接，重复启动与停止明确；旧 Close/Stop 不操作新运行资源。
- 同步表达式、枚举/null 校验、选中行删除、刷新/卸载保存与 Description。

### 6. Modbus

- RTU/TCP 操作持有真实事务；前台超时不提前放行给下一事务，实际未退继续隔离。
- 连接建立/关闭及同物理资源重开按精确 owner 和原代次管理；旧步骤不得使用下一轮同名连接。
- 校验从站地址位宽、寄存器数量/范围、布尔值与奇数字节输入；纠正 Holding 编辑映射及输出变量类型。
- 配置期限、参数解析异常边界及当前 DataGrid 编辑保存同步修复。

### 7. SerialPort

- 保留完整 Write→Read/Query 事务和未完成原生调用；终止符只切首条报文并保留剩余字节。
- 读取窗口和 Guard 原语义保持，打开/关闭期限可配置，不另加固定总等待覆盖用户配置。
- 中断/关闭后未退出仍持有原串口；释放后下一次首次打开正常，旧输出和旧配置不落到新运行。
- 读取/查询的设置反序列化纳入错误边界，补 null/枚举、UI 保存及 UTF-8 修复。

### 8. VISA

- 会话追踪真实 native I/O、取消回调和关闭完成；批量写与 WaitOPC 采用总预算。
- WaitOPC 严格验证设备返回 1，不把任意返回视为完成；期限属性配置失败仍保证归属与异常保全。
- 标量/波形结果采用文化无关转换和旧运行发布保护；旧关闭不影响新 Session/终止符。
- 七页表达式类型、校验与编辑保存修复；未新增仪器命令或假定所有仪器支持同一停止语义。

### 9. Ethernet

- TCP/DoIP 捕获连接池后复查原运行代次，避免迟到 Close 关闭新运行创建的连接池。
- DNS 和发送改用可取消异步路径；DoIP 排队、ACK 和诊断响应使用同一总预算，不按阶段重新获得完整期限。
- UDP/SOME-IP 无响应发送新增配置期限，UDP 检查完整数据报长度；非法传输枚举直接报错。
- 完成日志后再查原取消/期限，防止迟到输出；修复 DoIP 地址常量、变量类型和连接前置提示。

### 10. HTTP

- 客户端创建/替换失败回收本次临时资源；持久客户端不跟随已完成创建步骤的令牌关闭。
- 关闭等待实际请求及异步取消回调退出；前台超时不代表服务端事务已经撤回。
- JSON/XML 先完整解析与验证再发布输出，避免多变量只写一部分；请求头使用标准表达式列并可靠保存。
- 默认认证限定同源、避免自动跨源重定向泄露凭据，日志脱敏；未知枚举和非法期限不静默回退。

## 四、跨插件生命周期与手册一致性

新增私有共享实现 `Shared/Runtime/ExecutionEpoch.cs`、`PendingIoGate.cs`、`RetiringResources.cs`，以及 `Shared/UI/EditorSaveScheduler.cs`；由 `Directory.Build.targets` 源码链接进各插件，不增加一个需要集中部署的共享运行库。

1. **运行代次：**首次 await 前捕获执行资源代次，SDK CleanupExecution/CleanupAll 后旧步骤不得再取得新运行同名连接或发布结果。
2. **真实退出：**取消通知、软超时、后台任务退出、native 完成及设备动作完成是不同事实，分别记录；不清空尚未真正释放的物理占用来伪造重跑成功。
3. **资源归属：**同名活动连接不被静默替换；旧 owner 已安全退休可在配置预算内等完再开，旧清理不删新 owner。
4. **结果约定：**正常执行 Completed，执行故障/内部超时 Error，原调用方明确取消 Aborted；SDK ErrorInfo 保留中文说明和异常链。用户判断 Pass/Fail 交给序列判定步骤。
5. **界面闭环：**Setting 默认/兼容、Description、VM/实际页面及编辑时校验同步；Dispatcher 防抖、当前单元格提交、刷新/卸载 Flush，防止旧编辑回调写回其他步骤。
6. **编码：**中文文本 UTF-8；C# 无 BOM，其他文本保留项目所需换行/BOM 兼容性。

这使软件测试中的“运行中断→资源回收→第一次重跑”和“清旧调试资源表→新运行”具备确定保护；不把这些替身测试称为完整平台窗口实测。

## 五、插件树分层及兼容性

- CiA402 的 18 项 DisplayName 归入 `Session / State / Motion / Target / Feedback`。
- CANopen 共 14 项显示路径归入 `SDO / PDO / Network / Service / Cycle`（其中六项是新增步骤）。
- 六项 TCP/UDP 显示路径归入 `Ethernet_TCP / Ethernet_UDP`。
- 此前已有 StepTypeId 不改，不批量重写用户自定义步骤名；新增注册身份仅是六项 CANopen 与两项 AO。
- **显示名改变不是绝对零兼容影响：**工具箱路径、新建步骤默认名、搜索/文档及依赖名称的外部脚本可能需要调整。旧序列按 StepTypeId 识别，不依赖工具箱显示路径。
- CiA402 多 TPDO 设置有版本迁移与旧单 TPDO 保留；回退旧插件时应一并恢复适配旧结构的序列。
- 本轮最后一次勘误保持已经形成的 120 步骤身份/显示路径；这是相对前一阶段 120 项的兼容检查，不是声称相对云端没有新增步骤。
