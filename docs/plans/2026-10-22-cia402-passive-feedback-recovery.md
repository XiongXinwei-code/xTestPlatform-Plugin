# CiA402 被动反馈超时与已使能轴恢复

任务等级：L3（运动控制、取消传播、未完成 I/O 和恢复状态机）。保留既有工作区改动，只修改 CiA402 自身，不绕过父 CAN 的隔离。

## 证据与选择

- 现场链：反馈期限取消 → 轴传输持续隔离 → Unbind 停止/释能失败 → 驱动仍 OperationEnabled（5943/0x1737）→ Bind 拒绝 → 无会话，形成恢复状态循环；不是已证明的线程互锁死锁。
- 选择允许“只读绑定已使能轴”，不实现强行绕过隔离的独立 SDO 写入。绑定不会停轴、使能、切模式、重配 PDO 或覆盖目标，也不表示驱动已停稳。
- 区分被动 TPDO 与 SDO 反馈。SDO 读取也发送协议请求，超时可使共享事务失效，不能按“读/写”两个字笼统决定是否安全。
- 当前取消链确有令牌传递：反馈 → 节点接收 → 共享接收 → ICanAdapter.Read(ct)；取消瞬间 Task 未完成不等于令牌未传递，原生读取能否及时退出仍需硬件验证。

4. [x] 可选默认关闭的被动反馈能力：只有明确无协议请求的 TPDO 接收声明支持；超时后保持 I/O 门直到实际退出，退出后可重试，不因调度窗口永久污染整轴。

## 验收与兼容要求

- 保留 ICia402AxisTransport 既有方法，新增能力默认 false，旧 EtherCAT 后端保守处理；设置结构和步骤标识不变。
- 没有 TPDO 配置的反馈仍走 SDO，不参与被动接收恢复。共享 CAN 已因原生未退出或 SDO 中断失效时，仍须序列恢复通信，不能通过重新绑定清除。
- 同一时刻最多一个底层轴调用；被动接收尚未结束时，后续操作只可排队、取消或超时，不能另开通道写控制字，Dispose 仍延后释放。
- 反馈超时仍返回 Error 且不更新输出变量，表示本次反馈不可用/stale，不自动重试、不返回缓存成功；退避由序列决定。
- 纯读取绑定/解绑不改变电机状态。执行过控制步骤后，既有尽力停止与释能清理仍生效；即使 Enable 是幂等调用，也属于用户显式进入控制管理。
- 若监控序列仍在每次软超时后执行 Unbind，它会按原策略清理已受控的轴；重新 Bind 不自动恢复 Enable，恢复流程须明确编排。
- 不修改 NMT/SYNC 时序、目标值、驱动停止选项或父 CAN 生命周期，不把 ReadFeedback 偶发超时解释成物理卡死。
- 无真实板卡/驱动器；自动测试证明本地取消与错误传播，不证明实机停轴、安全链或现场缺帧起因。
