# CiA402 自身退出与资源生命周期修复

任务等级：L3。涉及运动控制、取消和并发资源回收。用户已明确：只修改 CiA402，父 CAN 连接由用户序列管理。

## 目标与范围

- 修复轴 Dispose 同步等待清理、步骤超时后资源回收继续阻塞的问题。
- 停止、执行失败、解除绑定和执行结束走同一个只启动一次的关闭流程。
- 使用统一清理期限；超时后禁止继续排队新的控制命令，实际未结束的 I/O 不强制重入或释放。
- CiA402 仅释放自身轴会话和 CANopen 节点占用，不关闭或包装 CAN 适配器。序列负责先解除绑定、再关闭 CAN。
- 保留现有运动模式、对象字典、PDO 布局和步骤设置的兼容性。

## 已核对的其他插件与平台约定

- CAN/LIN 周期任务使用 CancelAsync，未统一管理后台任务的实际完成和父连接释放顺序，不能直接照搬。
- Modbus 用 WaitAsync 为通信补软超时，但连接和传输层分别注册，不提供依赖清理协议。
- OPC UA 采集的 Dispose 仅取消，不能作为“运动清理已经完成”的证据。
- SDK 资源表默认 Execution 生命周期，回收入口为 IDisposable；未约定依赖排序或异步回收。

## 设计决定

- 关闭流程使用独立的 2000 ms 上限，不随着 60000 ms 通信设置增加；解除绑定调用方可以进一步缩短此期限。
- IDisposable 只发起关闭；CloseAsync/DisposeAsync 提供可等待的完成与错误结果。
- 原生调用不支持强制取消时保留占用；软超时只代表上层停止等待，不宣称硬件已停止或句柄已释放。
- 日志回调与控制清理分离，日志失败或阻塞不能阻止清理任务完成。
- 不修改 CAN 插件或资源表，不添加跨插件生命周期协调。外部先关闭 CAN 时及时报告停轴未确认，不重开连接。

## 风险与回退

- 无硬件时只能验证仿真及 SDK/WPF 契约，不能宣称现场停轴、驱动关闭和时序已通过。
- 已中断的 SDO 仍隔离迟到响应，不为发送停止命令而重新启用不可信的通信。
- 修复只改变 CiA402 生命周期和失败报告；回退到原 CiA402 版本即可，CAN 二进制接口不变。
