# 本地验证、云端备份与 UI 组件合入

本地测试先修复现有问题。完成验证后保存源码到新的云端备份分支，然后拉取 `origin/develop`。UI 集成使用从该快照建立的另一条本地分支。两阶段的修改边界不同。测试阶段可以修复本地源码；集成阶段只增加 UI 组件及必要依赖，若必须改原插件引用，先向用户说明。

1. 枚举各插件的测试工程，运行 Release 全量测试并保留每份 TRX。HTTP 和 Ethernet 的用例在 `PluginRegression.Tests`，ZLG 的独立运动套件另外运行。验收按测试总数、通过、失败、跳过逐项核对。
2. 对失败项区分正常保存、损坏数据读取、设备提交前校验及测试调度。保留生产保存校验，并用独立的测试输入验证编辑器与执行器是否真的拒绝错误输入。Modbus 与串口重点核对零请求、零读取、零发布，以及真实调用退出后才释放资源。
3. 对显式启用的 LabVIEW 联调，使用本地 NI LabVIEW 2026、VI Server 和官方算术样本副本，验证输入、输出及编辑页实际绑定。硬件协议与运动现场验收单独记录。任何失败或跳过均须列明，不作为回归通过项。
4. 从原工作树的实际内容建立独立 Git 索引快照，包含已跟踪的修改与非忽略新增文件。核对分支、原暂存区、逐文件指纹及测试结果，然后仅推送新的备份引用，并从远端回读提交 SHA。测试输出、转储、临时工作区和凭据不作为备份源码。
5. 云端备份核实后获取 `develop`。比较提交和文件，列出 UI 组件、直接依赖、与原插件交叉的设置。使用独立工作目录，从备份建立新本地分支，按路径选择内容，不整分支合并。原插件的实现与引用在此阶段保持备份提交的内容。
6. 验证新组件的构建、测试及必要运行行为，复核新分支相对备份的文件清单、原插件树哈希和原目录状态。回退依据为已确认的云端备份提交。只将备份分支写到云端，UI 集成分支留在本机。

采用 ECC planner、C# 审查、异常传播和验证方法。原始测试失败和修复后的结果均存放在 `artifacts/validation/2026-11-06-develop-ui/`。独立只读复核覆盖备份/工作树边界、非法设置的真实调用路径、阻塞测试及 Modbus/串口断言；实现者的自查与独立审查分别标注。
