# CiA402 首次终止原因与执行诊断

任务等级：L3（轴生命周期、取消和并发错误传播）。保留已有生命周期及多 TPDO 修改，不改父 CAN，不自动重绑或恢复运动。

## 已知证据

- 用户提供的堆栈停在 AxisSession.ExecuteAsync 的 `_closed` 入口检查；反馈及诊断尚未访问驱动，AxisName 不匹配不是这条异常的原因。
- 只读失败不会直接终止会话；控制失败/取消、绑定调用令牌取消、显式关闭或资源 Dispose 会终止会话。原实现丢弃首次原因，后续全部变成同一提示。
- staleCount 属于用户序列，不是插件内部计数。没有首次错误日志，不能将现场起因断言为 PDO、驱动故障或某个控制步骤。
- SDK 1.2.8 开发手册 §13.5：最终 Error 由引擎依据 ErrorInfo 统一记录；插件补充 ErrorInfo.Detail，不重复记录相同的最终 Error。取消和后台清理仍需要过程日志。

## 安全和兼容

- 不清除尚未结束的 I/O 隔离，不自动放行已终止会话，不增加 CAN 接收器、连接包装或驱动写入。
- 旧 AxisSession/传输接口入口保留；设置结构不变，不需要升级序列数据版本。
- 绑定步骤收到的 CancellationToken 不等同于已证实的全局运行令牌，日志仅描述实际来源，不推断宿主原因。
- 日志回调不得替换原始错误或阻止轴后台释放；首次原因独立存储，不能依赖有界日志队列是否成功写出。
- 无真实硬件；自动测试只验证错误传播、取消、并发、协议仿真及 WPF 契约，不能证明物理停轴或现场故障已根治。
