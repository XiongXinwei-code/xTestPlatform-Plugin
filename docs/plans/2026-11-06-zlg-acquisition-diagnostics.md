## 架构与取舍

1. `StartAcquisition` 新增公开强类型配置：`AcquisitionThreadPriority`（Normal / AboveNormal / Highest，默认 Normal）、`RxHighWatermarkPercent`（80，1～100）、`RxBacklogWarningMs`（10，1～60000）、`RxAlarmRepeatMs`（1000，100～3600000）。沿现有生成器同步 Setting/枚举、Description、VM、XAML、校验与助手契约。
2. 通过 Microsoft `Thread.Priority` 在现有 SDK 工作线程内部设置和回读优先级；影响该共享线程的采集、邮箱及输出调用，不冒称另有独立 RX 线程。成功启动前完成校验与优先级应用；失败保留既有诊断。停止/后台故障/关闭尝试恢复原优先级，恢复失败可见且仍允许关闭清理。不修改进程优先级，不使用实时优先级。
3. 单调时钟字段明确 `TimestampSource=HostMonotonicReadCompletion`、`TimestampFrequencyHz=Stopwatch.Frequency`、`HardwareTimestampAvailable=false`、`HardwareTimestamp=null`。原时间戳保留；本地年龄不包含此前 RX 排队时间，不能替代硬件采样年龄。SDO 反馈也只是主机完成时刻，不证明对象原子一致。
4. 新纯状态机 `RxQueueMonitor`：SDK 线程在 Pop 前后观察深度，记录容量、当前/峰值水位、连续非零观测、高水位/积压事件与恢复、采样间隔和观测年龄。观察到深度达到容量只锁存 `OverflowSuspected`，准确硬件丢失数始终 null。容量 0 不计算满队列；非 Queue 不宣称有队列监控。
5. 动态告警与“曾满”锁存分开；成功 Start 重置，Stop 保留最后诊断并标停止，不伪造恢复。`LatestOnly` 主动丢弃旧项、主机历史淘汰与读取项跳样分别说明，均不能冒充硬件覆盖数量。
6. SDK 线程只更新有界状态，通知保留一个最新摘要。利用已有后台读取池工作循环发送日志，按配置限制频率，无新线程/任务/计时器；不在监控锁或 SDK 线程调用宿主 Log。记录通知失败；关闭等待已有发布回调退出，禁止旧执行作用域再发新通知。
7. 采集状态使用缓存快照读取，SDK 阻塞/隔离时仍可查看最后观测年龄；监控自身不能在同一 SDK 线程阻塞期间实时发现新事件。池状态附带相同诊断。不以最后队列为空证明没有丢失。

Microsoft 依据：[Thread.Priority](https://learn.microsoft.com/en-us/dotnet/api/system.threading.thread.priority?view=net-8.0)、[线程调度](https://learn.microsoft.com/en-us/dotnet/standard/threading/scheduling-threads)。优先级不保证硬实时或指定时限。
