# LabVIEW 加载原生崩溃修复（L3）

用户在点击选择 VI 后收到 NI Error Reporter，平台 0.5.19.0 退出，异常码 0xC0000005。现场 dump 位于用户 Documents/LabVIEW Data/LVInternalReports/xTestPlatform/0.5.19.0/reports。原 1.0.28 的 95 项离线测试没有验证真实桥执行。远端 master e14cbf7c27bde7f4fd23765f610a92f6594fce29，插件手册与本地 3.4.0 一致。

## 范围与实施顺序

1. 只读取证，核对头文件、原生库和加载路径。解析实际异常模块，区分可证实问题与混载推测。
2. 增加独立 x64 辅助进程，平台生产入口全部通过继承的标准输入输出管道访问桥。共享有界 JSON 契约，固定程序路径，禁止 shell 和可执行命令注入。原生指针仅留在辅助进程。默认步骤参数和端子转换规则继续由现有类型维护。
3. 串行请求与调用票据衔接。取消前阻止提交，已提交请求继续等待真实返回，等待方按配置期限退出，后续请求保持拒绝。子进程意外退出记录 PID/退出码/阶段，不自动重新运行 VI。目标 LabVIEW 实例与用户进程不被终止。
4. 增加辅助进程异常退出、协议错误、超时后迟到、无旧请求补发、UI 配置保留的离线测试。构建核心、UI、辅助进程和可直接使用的插件包，核对包内文件与测试文件。
5. 独立只读审查原生 ABI 和并发/错误传播，修复并重测。真实 VI 加载复测需要可定位的样例及用户许可，不能以仿真宣布实机崩溃原因消除。

## 架构取舍与回退

辅助进程将 LabVIEW Runtime 与宿主已加载的第三方运行库分开，也隔离原生访问冲突。调用仍使用现有 VI Server 桥，避免在本次改变端子协议。跨进程有启动开销，辅助进程可在同一平台会话中复用。关闭输入端通知辅助进程在当前请求退出后结束，不把结束等待视为设备停止。回退为整体恢复 1.0.28 插件包，该包有已知同进程崩溃风险。

## 能力与验收

采用 ECC planner/architect、tdd-workflow、C# reviewer、silent-failure-hunter、security-review 与 verification-loop。边界重点为本机 IPC、固定子进程路径、有界消息、取消后的请求准入和未知执行结果。独立 ABI 审查由 lv_crash_abi 执行，最终生命周期另行独立只读复审。不修改 NI 注册表、设备配置、原 VI 或平台源码。最终记录实际通过、失败与未执行项。
