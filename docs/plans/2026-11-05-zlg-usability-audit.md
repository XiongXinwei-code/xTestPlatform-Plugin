# ZLG EtherCAT 全功能定位、映射与使用流程审查

任务等级：L3。用户要求逐项检查全部功能，消除同型号从站定位、参数读写范围和映射数据类型的歧义，并修复容易误用或无法使用的配置。目标仍为独立 ZLG 插件、HPCIe-2E、250/500 μs 与 DC；不执行现场设备动作。

## 范围与验收

- 覆盖现有 109 个步骤：板卡/通道、ENI/状态、PI/PDO、SDO、从站 I/O、两个读取池、运动、诊断、板载 I/O 与维护。
- 明确每步作用于板卡、通道、单个从站、轴或整个映像，区分从站零基索引、站地址、别名、板载端口及 PDO 相对/绝对偏移。相同型号不能作为唯一设备标识。
- 核对映射数据类型、位宽、符号、字节序、单位、缩放、边界与数据新鲜度；说明单值/字节数组/结构化结果与结果变量用法。
- Setting、Description、编辑器/VM、上下文与运行时校验一致。旧字段和 StepTypeId 保持兼容；必要新增显式字段保留旧配置语义，不能静默改变现有地址含义。
- 保留有意义的多从站/数据类型/异常路径回归；构建 Core/UI、实际 WPF 编辑器检查、严格程序集加载及源文件检查通过；发现问题须修复、重测和复审。
- 软件检查不证明真实 ENI/拓扑、驱动对象字典、250/500 μs、DC 或物理运动正确。

## 阶段与依赖

1. **证据与基线**：核对远端 master 手册（SHA `9ca9f70eb10a14cd9a931bcc3fe7fe5995da93d0`）、厂商 SDK 头文件/示例、当前契约与调用链。产出全部功能覆盖表与带位置的问题清单。
2. **职责和契约确认**：原生 SDK 以通道句柄及 SlaveIndex 定位；通道拥有唯一输入采集与输出映像；读取池仅提取配置的数据；运动映射限定明确的对象布局。以现有共享类型为契约，不引入额外接口框架。
3. **针对性修复**：先保留核心缺陷失败测试，再修复定位、边界或类型问题；生成器与生成源码同步。易用性修正覆盖目标/地址/结果/前置条件，并补足多同型号从站的使用示例。
4. **集成与复审**：构建、全模块离线测试、WPF 实际控件与严格加载；独立只读复核高风险修正。更新验收记录、用户文档及标准交付包，不混入研发文件。

## 架构与风险取舍

- 不按型号自动选择从站，不把 SDO CompleteAccess 解释成所有从站批量读写；PDO 整体采集与提取单站字段分开说明。
- 保持固定采集、周期读取与常驻读取工作循环；添加/更新/停止读取项只变更配置。
- 不默默统一旧运动绝对偏移与普通 PDO 相对偏移；如增加选择方式，须明确兼容默认、映射解析和回归验证。
- 设备类型/长度不匹配应报错，不做未经说明的截断、符号重解释或单位换算。驱动原始单位保留并清楚说明。
- 现有工作区存在其他未提交修改；不回退、不提交或部署。回退本次变更时仅恢复本次插件/图标/文档差异；协议及已有序列字段不删除。

## ECC 能力与执行安排

- 当前会话使用 ECC planner 与 architect 角色方法作一次规划及职责/数据流审查。
- C# 主审查采用 csharp-reviewer；由于设备动作、地址定位和共享状态，安排三个互补的独立只读审查范围：SDK与定位、PDO/池/运动、全部编辑器与流程。先审查再分配不冲突的修复文件。
- 核心缺陷采用 ecc:tdd-workflow 的失败复现→最小修复→回归方法；按项目约束不执行自动 Hooks，不因通用技能要求强制提交或覆盖率门槛。
- 超时、取消与恢复变更用 silent-failure-hunter 专项复核。若改动外部路径/解析边界，再触发 security-review；当前不扩展外部服务或权限接口。
- 最终采用 ecc:verification-loop；WPF 验证采用已有 STA 实际编辑器测试，结合 windows-desktop-e2e 的控件可操作性检查。完整宿主与硬件不可由离线测试代替，未执行时明确列出。
