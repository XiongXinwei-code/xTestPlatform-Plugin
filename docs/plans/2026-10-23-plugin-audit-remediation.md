## 架构取舍（实施前）

- 公共代码使用源码链接，不增加必须同时安装的新运行时公共 DLL；插件仍各自独立部署。共享 PendingIoGate 仅处理串行化、真实 pending、隔离和可确认关闭，厂商 Stop/Abort/Close 顺序由本插件负责，不能把不同 SDK 强行统一。
- 原始调用没有退出时，调用者可以 Error/Aborted 返回，但操作锁与句柄必须保留；后续访问拒绝，关闭等待有期限、实际收尾继续被追踪。步骤取消不代表报文撤回。
- 连接/任务默认有明确所有者；硬件建立前原子保留初始化 owner，完成验证后才可用于 I/O。Close/Stop 能冻结建立期，失败且未确认释放时保留登记供重试。关闭按实例/代次，不让旧故障关闭新连接。不同名称独立，恢复仍由序列控制。
- CAN/CiA402 保留现有父子职责、共享路由和隔离；不旁路父 CAN，不硬编码 TPDO 数量、不把 ACK 等同电机停稳。
- 不改已有枚举数值或删除/改名设置字段。新增设置同步模型、描述、UI、校验；不支持的能力明确拒绝，不伪装成功。
- UI 保存留在 Dispatcher，Flush 后才切换步骤；集合更改可保存。设备时序采用可信采集/入口时间，未知不冒充新鲜。
- NI 同步采集采用独立 AI/CI 资源和设备支持的共享时钟/触发，保留逐点数据，不复制单标量伪装同步。

替代方案：不重写所有插件、不关闭确认或忽略 Error、不自动重连、不用不等待退出的 Task.Run 作为安全修复。回退保留旧完整插件目录，版本只按原 patch 规则递增。

## 验证限制与结果记录

## 2026-10-24 追加：中断后立即重跑的全插件收尾

用户报告 NI:CAN1 在中断后重开被物理占用表拒绝，并要求覆盖全部插件。云端 master 使用直接 Dispose，本地新增所有权层用于补足原生调用实际退出确认，并非另设一套步骤开发范式；Open/Close、结果状态、设置与 UI 仍遵循同一手册。此前新增层的关闭与重开衔接存在缺陷，需要修复，不能回退到忽略 NI 接收线程、发送确认、Stop/Clear 结果的旧方式。

- CAN 保留物理独占；新 Open 对明确进入关闭的旧实例执行有界等待/重试。活动实例不接管，真实调用未退出不清锁；移除占用必须校验实例，记录关闭阶段与原始异常。原始读取链接连接生命周期令牌，但发送回显接收泵保留到发送收尾之后。
- 其他插件按真实资源标识追踪已经进入收尾的实例；私有源码链接的 RetiringResources 提供等待和失败后重试入口，不把已取消等待等同释放完成，不把不同名称的活动网络/OPC会话变成全局独占。SDK 的 Abort/Stop/Dispose 仍由各插件负责。
- 当前执行资源表退出后，必要的旧实例/实际任务/句柄仍由收尾记录持有；成功后按实例删除。内层 Close 的实际任务重用，外层只有一个单调总期限，自动 Dispose 的失败需可观察。
- 验收补充：Dispose 与下一次 Open 交错、迟到关闭不能删新占用、关闭失败后安全重试、取消有效/无效的原始读、旧 Open 迟到、独立连接不误关。保留不可恢复原生调用的明确 Error 和隔离，不承诺设备故障时强制重开成功。
- 能力继续使用现有 ECC 规划/架构、TDD、C# 与异常传播审查、最终验证。实现职责仍按插件目录隔离；集成后由非实现者独立只读审查生命周期改动。仅假适配器/本机loopback/STA验证，无硬件结论。
