# 全项目插件风险审查

等级：L3（跨插件、共享资源、设备动作与复杂并发）。本轮为只读审查，仅保存审查计划/证据/报告，不修改生产代码、序列、驱动或设备，不提交工作区已有修改。

## 范围与验收

当前10个插件：CAN、CiA402、Ethernet、Http、LIN、Modbus、NiDaq、OpcUa、SerialPort、VISA，以及配套UI、公共构建配置和依赖契约。第三方原生二进制不做全量逆向；生成图标等纯资源不逐像素审查。对入口、执行器、协议/适配器、资源所有者、后台任务及UI/设置保存进行定向源码阅读，单独记录覆盖与未验证范围。

1. 确认分支/未提交状态、项目/步骤/测试清单和依赖；建立当前基线，不沿用旧结论当作现状。
2. 按调用链逐插件审查：连接/重名/关闭、后台任务、超时/取消、并发读写、协议状态与数据校验、错误传播、UI/设置映射。
3. 对高风险发现交叉复核；能在无硬件条件复现的采用本地纯函数、假适配器或回环验证。无证据不宣称已复现，不把关键词命中当作缺陷。
4. 按适用范围构建全部核心和UI、运行已有CAN/CiA402假设备测试，输出到隔离artifacts；不连接真实设备或改变现场状态。
5. 输出按优先级排序的发现、触发条件、源码位置、影响、建议及验收方式；区分已确认缺陷、待现场验证风险和优化项。

## ECC 能力选择

当前Codex使用planner、csharp-reviewer与silent-failure-hunter方法，verification-loop验证；HTTP/证书/日志等信任边界补充security-review。只读审查不进行实现，不要求为每个发现修改代码或执行TDD。独立只读子Agent分组复核CAN/CiA402/LIN、Modbus/NiDaq/SerialPort、OpcUa/VISA；主Agent负责全局调用链、Ethernet/Http/UI和所有重点发现复核。禁止Agent修改文件或操作设备。

报告保存于docs/reviews/，记录实际检查结果；编译成功不等于协议、功能或硬件正确，已有测试也不等于所有插件都有测试覆盖。出现构建/测试失败时先收集证据，本轮不擅自修复生产代码。
