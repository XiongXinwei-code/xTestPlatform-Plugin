# 全插件生命周期与阻塞审查（2026-10-24）

## 范围与边界

- 等级：L3。审查当前工作区全部 10 个插件模块、118 个步骤及其连接、后台任务、取消与释放调用链。
- 本轮是只读诊断，不修改生产代码、不操作设备、不替换交付插件、不提交或推送。工作区已有大量未提交修改，不拉取覆盖；HEAD 为 `5351a0a9d66594455b292fe65308303488a07537`，结论以本轮源码指纹为准。
- 核心场景：打开/启动、正常执行、内部超时、外部中断、显式关闭、宿主资源回收、立即重跑、重复关闭/打开、后台故障。
- 区分三个事实：调用方停止等待、真实 I/O/线程退出、驱动与物理资源释放。不能以取消令牌或 ACK 代替后两者，也不能通过删除所有权掩盖仍活动的原生调用。

## 阶段与验收

1. 固定审查基线与覆盖清单：记录源码指纹、插件/步骤/版本、生产与测试项目、开发手册约束；核对现有交付 DLL 的来源。验收为 10 个模块均有覆盖记录，历史通过不冒充本轮运行证据。
2. 按调用链审查：资源创建失败回滚、运行排队与预算、取消传递、同步阻塞、后台异常传播、关闭重试和物理占用表。验收为每项问题有文件行号、触发条件、影响及依据，区分已证实缺陷、条件性风险与未验证边界。
3. 定向离线验证：使用现有假适配器/纯托管探针复核高风险交错，禁止实际总线、串口、PLC、仪器或运动动作。验收为记录实际命令、输出和局限；没有运行的场景不得标通过。
4. 独立只读审查：由原生子 Agent 交叉检查非本人近期实现的模块，重点取消/恢复与共享状态；不并行修改生产代码。主 Agent 核实结论并合并去重。
5. 最终报告与自查：按严重度给出待修清单、全模块矩阵、建议验收、硬件/宿主运行缺口，检查 UTF-8、定位与最终指纹。验收为报告不宣称已修复或现场已通过。

## 能力选择与取舍

- ECC `planner`：当前 Agent 按已读取方法制定本计划；不另起重复规划流程。
- ECC `production-audit`：全仓生命周期、实际证据、故障恢复和交付边界审查。
- ECC `architect`：分析资源所有者、异步门、退役登记与宿主回收间职责；本轮不改变架构或公共接口。
- ECC `csharp-reviewer` 与 `silent-failure-hunter`：审查实际 C# 调用链、同步等待、预算/令牌、吞错、晚到释放及隔离恢复。
- ECC `verification-loop`：使用匹配审查任务的指纹、定向离线测试、报告差异检查。没有生产代码更改，不重复无变化的全部 UI 构建。
- 独立审查必要：涉及设备通信、复杂并发、取消与资源恢复。只读 Agent 的结果须由主 Agent 核实；不得把自审写作独立审查。
- 本轮不采用 TDD/接口契约工具：没有实施行为/API 修改；确认的缺陷附后续失败测试建议。若转实施，另行遵循缺陷复现驱动修复。
- 无实际平台、NI SDK/硬件运行证据，不进行现场安全、UI 卡死或总线时序验收；不加载不相关安全扫描/外部服务。

## 风险与回退

- 当前源码与历史同版本 DLL 可能不同，必须区分源码、离线程序集探针及用户实际加载版本。
- 原生驱动卡住时，隔离并保留所有者可能是正确保护，不能承诺立即重新占用；应能在配置期限内异步报出未退出而不占住宿主线程。
- 报告和探针仅写入 `docs/` 与 `artifacts/plugin-lifecycle-audit/`；回退只需移除本轮新增文档/探针，不涉及生产代码。
