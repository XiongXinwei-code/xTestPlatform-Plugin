# 硬件插件「仿真模式」改造成本评估

> 目标：插件业务逻辑真实执行，仅将最底层硬件调用替换为假实现。
>
> 本文所有结论均来自对 `D:\xTestPlatform-PluginDev` 当前 `develop` 分支源码的实际检索，文件路径与行号已逐一核对，不含推测。

## 1. 插件项目清单与硬件访问性质

解决方案共 10 个功能域，每个域包含 `XxxPlugin`（执行层）与 `XxxPlugin.UI`（编辑器层）两个项目。

| 功能域 | 执行层项目 | 访问真实硬件 | 底层通道 |
|---|---|:---:|---|
| CAN | `CAN\CanPlugin` | 是 | 原生 DLL P/Invoke（ZLG / Vector / Kvaser / Tosun / PEAK / NI-XNET） |
| LIN | `LIN\LinPlugin` | 是 | 原生 DLL P/Invoke（NI-XNET） |
| NI-DAQ | `NiDaq\NiDaqPlugin` | 是 | NationalInstruments.DAQmx 托管 SDK |
| LabVIEW | `LabVIEWCall\LabVIEWCallPlugin` | 是 | 原生 `lvLib.dll` P/Invoke |
| VISA | `VISA\VisaPlugin` | 是 | IVI VISA（GPIB / USB / TCPIP 仪器） |
| 串口 | `SerialPort\SerialPortPlugin` | 是 | `System.IO.Ports.SerialPort` |
| Modbus | `Modbus\ModbusPlugin` | 是 | NModbus + `TcpClient` / `SerialPort` |
| 以太网 | `Ethernet\EthernetPlugin`（TCP / UDP / DoIP / SOME-IP） | 是（网口） | `TcpClient` / `UdpClient` |
| OPC UA | `OpcUa\OpcUaPlugin` | 是（网口） | OPC UA SDK `Session` |
| HTTP | `Http\HttpPlugin` | 否 | `HttpClient`（BCL，应用层协议） |

**结论**：不存在完全纯逻辑的插件项目，`Http` 是最接近的一个（仅使用 BCL `HttpClient`，无第三方驱动依赖）。

## 3. 连接对象的持有方式

### 3.1 `context.Resources`（会话级，跨步骤复用）—— 主流模式

| 域 | 写入（Open/Connect） | 读取（Read/Write/Close） |
|---|---|---|
| CAN | `Executors\CanOpenExecutor.cs:39` | `CanReadExecutor.cs:25`、`CanWriteExecutor.cs:25`、`CanCloseExecutor.cs:26`、`CanCyclicSendStartExecutor.cs:26` |
| LIN | `Executors\LinOpenExecutor.cs:39` | `LinReadExecutor.cs:25`、`LinWriteExecutor.cs:25`、`LinWriteReadExecutor.cs:26`、`LinSleepExecutor.cs:26`、`LinWakeupExecutor.cs:26`、`LinCloseExecutor.cs:26` |

| Modbus | `Executors\ModbusConnectExecutor.cs:62`（transport）、`:63`（master）、`:67`（超时值） | `ModbusReadExecutor.cs:31`、`ModbusWriteExecutor.cs:31`、`ModbusBatchReadExecutor.cs:31`、`ModbusBatchWriteExecutor.cs:31`、`ModbusDisconnectExecutor.cs:34-38` |
| VISA | `Executors\VisaOpenExecutor.cs:34`（session）、`:35`（终止符） | `VisaReadExecutor.cs:31`、`VisaWriteExecutor.cs:31`、`VisaQueryExecutor.cs:32`、`VisaBatchWriteExecutor.cs:29`、`VisaWaitOpcExecutor.cs:30`、`VisaCloseExecutor.cs:31-32` |
| OPC UA | `Executors\OpcUaConnectExecutor.cs:80` | `OpcUaReadExecutor.cs:29`、`OpcUaWriteExecutor.cs:30`、`OpcUaBatchReadExecutor.cs:28`、`OpcUaBatchWriteExecutor.cs:28`、`OpcUaSubscribeExecutor.cs:30`、`OpcUaDataAcqStartExecutor.cs:30`、`OpcUaDisconnectExecutor.cs:27` |
| HTTP | `Executors\HttpClientCreateExecutor.cs:71` | `HttpClientCloseExecutor.cs` |

**确认存在「Open 一个步骤、Read 另一个步骤」的跨步骤连接复用**，这是本仓库的标准模式。

Modbus 因 NModbus 异步方法不接受 `CancellationToken`，额外把超时值随连接存入 `Resources`（`ModbusConnectExecutor.cs:65-67` 注释说明），供后续读写做软超时兜底。

VISA 使用 `ConditionalWeakTable` 为每个会话维护互斥锁（`VISA\VisaPlugin\Helpers\VisaHelper.cs` 顶部）。

### 3.2 static 全局字典（进程级，脱离测试会话）

- `Ethernet\EthernetPlugin\TcpConnectionManager.cs:9` — `private static readonly ConcurrentDictionary<string, TcpClient> _clients`
- `Ethernet\EthernetPlugin\DoIP\DoipConnectionManager.cs:9` — `private static readonly ConcurrentDictionary<string, DoipClient> _sessions`

`TcpConnectionManager.ConnectAsync` 在同名连接已存在时先 `TryRemove` 并关闭旧连接（`:19-23`），`Get` 在连接不存在或已断开时抛异常（`:45-47`）。

### 3.3 变量表持有（NI-DAQ）

NI-DAQ **不使用** `context.Resources`，改用变量表：

- `NiDaqAiConfigExecutor.cs:75`、`NiDaqEncoderConfigExecutor.cs:57`、`NiDaqSyncConfigExecutor.cs:94` — `context.SetVariable(taskName, task)`
- `NiDaqTaskStartExecutor.cs:33` — 取出后 `task.Start()`

### 3.4 每次执行新建、用完即弃

- 以太网全部 UDP / SOME-IP / DoIP 发现类步骤（见 2.2 列表，均为 `using var udp = new UdpClient(...)`）

## 4. `ctx.Resources.GetOrAdd(...)` 使用情况

**全解决方案 0 处使用。**

实际使用的 `Resources` API 仅有三个：`Set(key, value)`、`TryGet<T>(key, out value)`、`Remove(key)`。

若仿真改造需要「按连接名惰性创建假设备」，需自行用 `TryGet` + `Set` 组合实现，或先在宿主侧补充 `GetOrAdd`。

## 5. 跨插件共用的底层驱动封装

### 5.1 存在共用：CAN 域内

UDS、XCP、Flash 三套高层协议**全部复用 CAN 的同一个 `ICanAdapter` 实例**，不自建连接：

- 键生成统一入口：`CAN\CanPlugin\Helpers\CanHelper.cs:10` — `GetAdapterKey(connectionName)`
- UDS：`CAN\CanPlugin\UDS\UdsExecutorHelper.cs:20`（取适配器）→ `:30` `new UdsClient(adapter, txId, rxId, ...)` → `UDS\UdsClient.cs:70` `new IsoTpTransport(adapter, txId, rxId, frameType, useFd)`（`UDS\IsoTp\IsoTpTransport.cs:30` 构造函数接收 `ICanAdapter`）
- XCP：`CAN\CanPlugin\XCP\XcpExecutorHelper.cs:19-20`

> **这是唯一一处跨插件族共享的驱动封装。** 只要替换 `ICanAdapter`，UDS / XCP / Flash 全部自动进入仿真，无需单独改造。

### 5.2 不存在共用（各自独立实现）

- `CanPlugin` 与 `LinPlugin` **各自实现自己的 NI-XNET P/Invoke**（`CAN\CanPlugin\Adapters\NiXnet\` 与 `LIN\LinPlugin\Adapters\NiXnet\NiXnetLinApi.cs`），无共享层。
- Modbus RTU 自行 `new SerialPort`（`ModbusConnectExecutor.cs:50`），**不复用** `SerialPortPlugin` 的连接与 `Resources` 键。
- Modbus TCP 自行 `new TcpClient`（`ModbusConnectExecutor.cs:40`），**不复用** `Ethernet` 的 `TcpConnectionManager`。

## 6. 改造成本速判

| 成本 | 域 | 理由与切入点 |
|---|---|---|
| **低** | CAN | 已有 `ICanAdapter` + 工厂，只需新增 `SimCanAdapter` 并在 `CanAdapterFactory.cs:12-17` 加分支。UDS / XCP / Flash 一并受益 |
| **低** | LIN | 已有 `ILinAdapter` + 工厂，切入点 `LinAdapterFactory.cs:12` |
| **低** | VISA | `OpenSession` 返回的是 `IMessageBasedSession` 接口，在 `VisaHelper.cs:38` 单点分流即可 |
| **中** | 串口 | 需抽出接口，但调用点集中在 `SerialPortOpenExecutor.cs:37-48` 与 4 个读写执行器的 `TryGet<SysSerialPort>` |
| **中** | Modbus | 需抽出接口；`IModbusMaster` 本身是接口（利好），但 transport 是具体类型。切入点 `ModbusConnectExecutor.cs:35-56` |
| **中** | 以太网 TCP / DoIP | 连接创建集中在两个 `*ConnectionManager`，但 UDP 类步骤散落 7 处需逐个处理 |
| **高** | NI-DAQ | `DaqTask` / `*Reader` 为具体密封类型，调用点散落在 8 个执行器。建议以 `NiDriverCheck.cs:21` 为总开关 + 抽出 DAQ 门面层 |
| **高** | OPC UA | `Opc.Ua.Client.Session` 是具体类而非接口，`Session.Create`（`OpcUaConnectExecutor.cs:69`）难以直接假实现，需引入自有门面接口 |
| **高** | LabVIEW | `LvLibWrapper` 全为 `static extern` P/Invoke，无注入点。需在 `LvLibHelper` 层做门面抽象 |

### 需特别注意的风险点

1. **仿真开关的存放位置不统一**：主流插件的连接挂在 `context.Resources`（会话级），但 `Ethernet\EthernetPlugin\TcpConnectionManager.cs:9` 与 `DoIP\DoipConnectionManager.cs:9` 用的是 **static 进程级字典**。仿真开关若只挂在测试上下文上，这两处拿不到，需另设进程级开关或改造为会话级持有。
2. **NI-DAQ 走变量表而非 Resources**：仿真任务对象要能被 `context.GetVariable` 取回并通过类型检查，替身类型需与 `DaqTask` 兼容或同步改造所有取用点。
3. **无 `GetOrAdd`**：惰性创建假设备需自行用 `TryGet` + `Set` 实现，注意并发与同名覆盖语义（现有代码依赖 `Set` 自动销毁同名旧资源，见 `SerialPortOpenExecutor.cs:52` 与 `ModbusConnectExecutor.cs:61` 的注释）。
4. **CAN 与 LIN 的 NI-XNET 重复实现**：若未来打算合并，仿真改造是一个合适的时机；但当前需按两套分别处理。
