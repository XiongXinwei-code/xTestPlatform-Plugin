## 功能概述

通过 OPC UA 协议与 PLC、SCADA 等服务器通信，支持节点的单点与批量读写、订阅监控以及后台数据采集的启停与读取。

## 支持的硬件/协议

- 任何符合 OPC UA 规范的服务器（如西门子、倍福 PLC）

## 包含的步骤

| 步骤 | 说明 |
|------|------|
| OpcUa_BatchRead | 批量读取 OPC UA 服务器中多个节点的值，每个节点的结果分别存入对应变量。 |
| OpcUa_BatchWrite | 批量向 OPC UA 服务器中多个节点写入值。 |
| OpcUa_Connect | 建立 OPC UA 连接，支持匿名和用户名密码认证以及多种安全策略，连接成功后通过 ConnectionName 标识。 |
| OpcUa_DataAcq_Read | 从运行中的 OPC UA 采集任务的 FIFO 缓冲中读取（消费）数据，构造为波形写入变量，可选追加导出 CSV。 |
| OpcUa_DataAcq_Start | 启动 OPC UA 后台数据采集任务，按指定采样间隔定时读取多个节点并写入有界 FIFO 缓冲（仿硬件采集卡模式）， |
| OpcUa_DataAcq_Stop | 停止 OPC UA 后台数据采集任务并释放资源。未被消费的缓冲数据将被丢弃，如需读取请在 Stop 前执行 OpcUa_DataAcq_Read。 |
| OpcUa_Disconnect | 断开指定的 OPC UA 连接并释放资源。 |
| OpcUa_Read | 读取 OPC UA 服务器中单个节点的值，并将结果存入指定变量。 |
| OpcUa_Subscribe | 订阅 OPC UA 节点并等待其值满足指定条件，用于等待 PLC/设备状态变化的场景。 |
| OpcUa_Write | 向 OPC UA 服务器中单个节点写入指定值。 |

## 使用前提

需保证 OPC UA 服务器地址可达，并按服务器要求配置安全策略与凭据。

## 中断、调试重入与采集

- 连接独占自己的 Session、真实 SDK 请求、取消回调和采集任务。调用方取消只结束本步骤的等待；原始 SDK 调用或取消回调未退出时保留 owner，禁止把晚到结果发布为成功。停止/断开等待受步骤配置期限限制，超时不代表服务器已释放 Session。
- 同 endpoint、不同连接名允许独立连接；关闭一个连接不主动关闭其他名称的 Session。不提供自动重连，恢复由序列控制。同名旧连接正在回收时，新执行或新调试资源表先等待真实收尾；永久不退出时明确报错，不强清占用。
- 采集循环停止与消费/CSV 导出完成分别追踪。即使达到最大采集时长，连接仍持有采集 owner，直到真实关闭；断开不会漏掉自然结束后的消费者。后台读取失败或非 Good 质量记录诊断并继续轮询，FIFO 溢出会停止采集；请检查健康状态，不能只看数据条数。
- `DataAcq_Read` 可只导出 CSV 或 JSON，不强制配置波形变量。追加 CSV 部分写入失败时，路径保持“写入结果未知”隔离，禁止盲重试导致重复；此状态跨同进程的采集 owner/调试上下文保留。请检查文件后更换输出路径或重启插件，不将其视为正常中断遗留占用。
- 标量读写、批量读写与订阅使用正数有限期限（不支持 `-1`）。Auto 数值写入同显式数值转换一样使用不带千位分隔的 invariant 格式，例如 `1.5`；拒绝 `NaN`、无穷及 `1,5`。未知安全策略/认证枚举直接报错，不降级为无安全/匿名。

本轮使用真实平台 SDK 的资源注册表验证 `CleanupExecution`/`CleanupAll` 后同表及新注册表重开顺序，并运行 WPF 组件与假 SDK 测试；未连接 OPC UA 服务器，未进行完整平台调试窗口端到端验证。当前证据见 `artifacts/full-plugin-audit-20261024/initial-nidaq-opc.md`，不以构建/替身通过代替现场验证。

第一轮独立勘误补齐了外层变量发布和日志后的原 caller/精确连接实例围栏。采集 Stop 固定首次 `TryGet` 返回的目标，再通过关闭代次使此前未完成 Start 失效；后续不按名称重新捕获新任务。它不是跨注册表原子事务：关闭标记前未完成的并发 Start 允许被判失效，但 Stop 不会关闭捕获实例之外的后来 owner。批量写实际类型下拉已提供枚举选项，采集空列名按既有 NodeId 回退兼容。

旧 Connect/Disconnect/采集 Stop 的期限从名称/端点表达式求值后开始；旧读写/订阅的期限覆盖其文档约定的 SDK 阶段，不包含任意表达式求值。入口及求值后检查原 caller，取消后不发起后续 SDK 动作；AcqStart/AcqRead 已有的表达式+消费/SDK 同一总预算保持不变。表达式引擎非协作卡住能否由宿主中止未在本轮验证。

全部 10 步在首次等待前捕获 SDK 执行代次。回收后即使原 caller 未取消，旧连接建立/采集启动/读写续体也不能使用新运行的同名 owner 或发布晚结果；代次失效返回 Error，宿主显式中断或 caller 取消返回 Aborted。连接保存的是执行代次，不是创建步骤的取消令牌；已启动的真实 Delete/SessionClose 收尾不受普通提交围栏阻断，迟到失败清理仅移除自己的精确实例。第二轮软件证据见 `artifacts/full-plugin-audit-20261024/round2-nidaq-opc-epoch.md`。
