## 1.0.5

- BindAxis 改为无副作用关联：允许绑定已使能、QuickStop 或故障态的未占用轴，只读核对控制字、状态字及已配置 PDO 映射，不自动停轴、使能、切模式或覆盖目标。绑定时状态写入日志和轴快照，UI 明示“绑定成功不代表驱动已停止”。
- 修复被动 TPDO 接收超时因取消调度窗口导致整轴持续隔离：原接收实际退出后允许退避重试，SDO 诊断与后续控制不再被这一次纯接收超时永久阻断；调用未退出前仍保留 I/O 门，禁止重入及提前释放。
- 新增 FeedbackIsPassiveReceive 能力，默认 false；CANopen 仅配置 TPDO 反馈时声明，被动接收以外的 SDO 读写、RPDO 发送及旧 EtherCAT 后端保持保守隔离。下层共享 CAN 的 SDO/原生调用失效保护不清除，不另开 SDO 绕过隔离。
- 反馈缺帧仍返回 Error，表示本次反馈无效，不更新输出变量、不返回缓存成功、不自动重试。日志区分“等待结束时尚未退出”“当前等待被动接收退出”和“持续隔离”。
- 原有控制步骤的状态与安全初值检查、控制后的有界清理保持不变。只读绑定/读取/解绑不主动停轴；执行过控制步骤（包括幂等 Enable）后，解绑仍尝试停止与释能。重新绑定不自动恢复使能或旧周期目标。
- 新增 18 项无硬件恢复与 WPF 布局回归，全量 204/204；验证被动接收退出后可继续、原生不退出时仍被共享 CAN 隔离、清理失败后使能态只读重绑及显式 PV。绑定状态日志使用既有有界队列，日志异常不撤回成功会话。
- 设置结构、步骤标识和 CAN 插件源码不变，可回退 1.0.4，但会恢复旧的拒绝使能态绑定及被动接收持续隔离问题。真实硬件退出、停轴、NMT/SYNC 与现场缺帧起因仍须验证。

## 1.0.4

- 修复绑定步骤调用令牌被当作共享轴会话生命周期的错误：BindAxis 不再让已注册的会话长期订阅本次绑定的令牌，防止绑定调用结束后其令牌取消导致后续反馈与故障码读取持续报“轴会话已终止”。现场 1.0.3 首次终止日志已确认该触发链。
- 轴会话显式注册为 Execution 资源，由解绑或平台执行资源回收关闭；不是屏蔽停止。绑定初始化/注册仍响应本步骤取消和期限，后续控制步骤自身取消仍终止本轴并执行有界清理，不改父 CAN。
- 注册阶段取消或失败时撤回本次创建的轴资源，只移除引用仍属于本次绑定的会话；保留原始异常及失败时轴快照。显式外部会话生命周期令牌构造 API 保留，来源日志改为“显式轴会话生命周期令牌取消”，不得传入步骤级令牌。
- 设置结构与 1.0.3 相同，无须修改轴名、反馈映射或重新编排序列；回退 1.0.3 会恢复绑定令牌误终止缺陷。实际宿主停止/退出和硬件停轴仍需现场验证。
- 新增 4 项真实 BindAxis 执行入口的无硬件回归：绑定后取消原令牌仍可反馈/诊断、初始化取消、注册时取消回撤及后续控制自身取消。现场同型用例在修改前失败，修改后通过，全量共 186 项。

## 1.0.3

- 修复终止会话丢失首次原因的诊断缺陷。后续反馈、故障码及其他步骤返回原始触发步骤、地址、首次终止时间、会话标识和原始异常，不再只提示重新绑定；清理失败或重复 Dispose 不覆盖首故障。
- 统一 ErrorInfo.Detail：记录插件版本、已解析轴名、绑定连接/节点、执行阶段、耗时、步骤及单次通信期限、取消状态和完整异常链。遵循 SDK 1.2.8，由引擎统一记录最终 Error，不重复输出；主动取消保留单独过程日志。
- 区分步骤总期限、会话/后端取消、显式解除绑定、绑定步骤调用方令牌取消与资源回收。绑定收到的令牌没有全局运行来源证明，不再将其日志误写成已确认的全局停止。
- 单次通信异常附带对象索引/子索引、读写方向及排队/I/O 阶段；传输隔离保留第一次未退出调用的原因。CANopen 反馈错误增加所需/已收/缺失 TPDO、正在等待 ID、重复/过期丢弃计数和有效期，即使外层期限先结束也保留最近快照。
- 不改变控制失败后的终止保护，不自动恢复使能、清除隔离、重新绑定或管理父 CAN。设置结构与 1.0.2 相同，可回退至 1.0.2；实际现场首故障仍须结合新版日志和硬件确认。
- 新增 13 项首故障、超时分类、排队取消、资源移除后快照、只读失败恢复、多轴隔离和第三方日志/异常兼容回归，全量共 182 项。

## 1.0.2

- BindAxis 新增可增删、逐项编辑的多 TPDO 反馈列表；保留旧单 TPDO / SDO 字段和默认行为。设置结构升级至 2，自动迁移版本 1，其他步骤标识和设置不变；回退旧插件须同时还原旧序列备份。
- 多 TPDO 按所需字段收集，逐 COB-ID 跟踪时间戳，复核队列年龄与帧间时间窗口，所有帧共用通信期限，不用上次调用结果补缺，不隐式发送 SYNC/RTR。
- 反馈映射允许附带其他已核对对象，集合整体含状态字即可；重复反馈字段使用配置顺序中的第一个来源。提前校验对象类型、位数、重复编号及目标 RPDO / 反馈 TPDO 的 COB-ID 冲突。
- 修复 Enable 继承旧运动启动位和 PV/PT 遗留非零目标：从未使能状态进入时撤销旧启动选项、PV/PT 预置零目标；已经使能时保持幂等，不改变正在执行的目标。
- 模式显示已匹配时仍检查驱动故障及意外状态，避免仅凭 0x6061 返回成功；非使能态模式切换不继承旧控制字中的 Enable Operation，避免意外恢复运动。统一诊断空输出校验，补充初始化失败后的异步释放错误日志。
- 同名轴的绑定/解绑在本插件内串行化，避免旧解绑检查和移除之间的竞态误删新会话；排队受步骤期限和取消约束，不接管父 CAN 资源。
- 新增 37 项功能、兼容、生命周期及 WPF STA 表格编辑回归，合计 169 项；保留上一轮退出修复，不修改父 CAN 生命周期。实际驱动器行为仍需硬件验证。

## 1.0.1

- 重构 CiA402 自身资源生命周期：停止、控制失败、解除绑定和自动回收共用单次关闭流程；同步 Dispose 不再等待硬件清理。
- 清理等待统一限制在 2000 ms 内，覆盖活动操作退出、停止/释放使能及底层释放；步骤期限可进一步缩短，不随单次通信超时累加。
- 显式解除绑定报告清理失败、超时和底层释放错误；及时移除终止会话，控制失败不被后台清理拖延或替换原始异常。
- 取消后不再追加新的清理命令，未结束 I/O 保留占用并延后释放一次；绑定初始化失败及 EtherCAT 工厂晚到实例也进行隔离释放。
- 清理日志改为有界异步写入，记录阶段耗时，不因宿主日志阻塞或抛错拖住回收。
- 仅管理轴会话和节点占用，不修改父 CAN 生命周期、SDO/PDO 编码、运动状态机或既有步骤配置；仍须显式先解除绑定再关闭 CAN。
- 新增 18 项无硬件生命周期回归，连同原有用例共 132 项；实际驱动停轴、CAN 板卡与宿主退出仍需现场验证。回退时替换回原 CiA402 核心/UI，不需修改 CAN 插件。
