# CiA402 驱动状态与运动插件

## 本轮修订 v1.0.11

本次生命周期机制修订：轴前台等待与实际活动操作分离；传输等待及取消回调按真实退出释放，父 CAN 仍由 CAN 插件独立管理。
软件复现、非作者复审与三轮勘误见源码仓库 docs/reviews/2026-10-26-plugin-lifecycle-mechanism.md。完整平台窗口及真实设备仍未验收。

本轮轴步骤控制语义保持，私有CAN依赖同步至1.0.38；未改变PDO布局、停机控制字或物理停稳判据。

设置字段、枚举与步骤身份保持兼容；非空输出须按手册显式声明完整变量路径。软件验证与三轮勘误记录在源码仓库 docs/reviews/2026-10-25-plugin-lifecycle-followup.md。真实平台调试窗口和设备尚需验收。

## 反馈时间与编辑保存兼容说明

- PDO 新鲜度必须具有 CAN 适配器提供的 `CaptureMonotonicLowerBoundTicks` 证据；只有主机入队时间的帧仍可诊断，但不会被视为新鲜反馈。未知时间将计入错误详情，不在出队时重新计时。没有可信时钟映射的硬件应使用经验证的 SDO 反馈方式或先完善其采集时间能力，不能通过放宽有效期伪造新鲜度。
- 18 个步骤编辑器在保存命令失败后保留原步骤的待保存动作。重试成功前拒绝切换步骤，卸载时仍 Flush；异常会显示在编辑器错误信息中。此变更不改变序列字段、枚举或 StepTypeId。
- 未进行电机、实际 CAN 帧时序或停轴安全实测；协议 ACK 不代表电机已停稳。

## 功能与边界

一套插件、十八个单职责步骤，共享协议无关状态机和轴会话。首期提供 PP(1)、PV(3)、PT(4)、HM(6)、CSP(8)、CSV(9)、CST(10) 操作。

- CANopen 复用 CAN_Open 的连接，提供 SDO 状态/参数访问及显式 PDO 目标和反馈。
- EtherCAT 仅提供 `ICia402EtherCatFactory` 扩展契约，不包含主站 SDK；没有注册工厂时明确报错。
- **CSP/CSV/CST 由测试序列循环编排，是非实时周期控制，不保证确定性周期。** 不提供轨迹插补、实时多轴同步或后台周期服务。
- 驱动必须支持选择的模式、对象和通信周期。不能通过屏蔽驱动保护或无限放宽超时掩盖通信能力不足。
- 本版本需要实际设备联调；编译或仿真通过不等于硬件兼容性已经验证。

## 轴与通信配置

1. 执行 CAN_Open。CAN 适配器必须支持经典 CAN 标准帧。
2. 按设备手册用 CANopen 配置步骤设置 PDO、传输类型、SYNC 周期和 NMT 状态。
3. 执行 BindAxis，填写 AxisName、ConnectionName、NodeId；字符串表达式默认使用带引号的字面量。
4. 绑定同名轴或已占用节点时报错；不静默替换。允许绑定已使能、QuickStop 或故障态的轴，但绑定不主动停轴、使能、切模式或修改目标，成功不代表驱动已停止。
5. 后续步骤只使用 AxisName；结束时先解除绑定，再关闭 CAN。

ObjectIndexOffset 用于标准 0x6000~0x67FF 轴对象的显式索引偏移。PDO 布局与硬件诊断索引填写实际地址，不自动追加偏移。非标准多轴布局需要后续设备适配，不应猜测对象地址。

### PDO 映射

CspPdoNumber/CsvPdoNumber/CstPdoNumber：0 表示未配置；1 对应 RPDO 通信参数 0x1400、映射参数 0x1600，以此类推。绑定时读取设备对象字典核对映射，不自动更改设备。

布局为普通配置文本，不是表达式：`索引:子索引:位数`，多个项以逗号分隔。

- CSP 示例：`0x607A:0:32`。
- CSV 示例：`0x60FF:0:32`。
- CST 示例：`0x6071:0:16`。
- 可附加当前轴控制字，例如 `0x6040:0:16,0x607A:0:32`；控制字由会话统一管理。
- 每个目标 PDO 只能包含该模式目标和可选控制字，不支持未赋值的额外输出项。
- 不同模式使用不同 RPDO；只支持已启用的标准帧 PDO，不支持 RTR 请求式反馈。
- 调用目标步骤不会隐式发送 SYNC；PDO 与 SYNC 顺序按驱动配置编排。

默认 `UseMultipleFeedbackPdos=false` 保留旧设置：FeedbackPdoNumber 为 0 时使用 SDO 顺序读取，非零时选择单个含状态字的 TPDO，例如 `0x6041:0:16,0x6064:0:32,0x6077:0:16`。每帧最多 8 字节，该示例不能再加入速度。

需要同时反馈位置、速度和转矩时，在 BindAxis 编辑器勾选“使用多个反馈 TPDO”，在列表添加实际设备支持的编号和完整映射。以下仅为配置示例，设备实际映射须提前由用户序列配置：

| TPDO 编号 | Layout | 反馈内容 |
|---|---|---|
| 1 | `0x6041:0:16,0x6064:0:32` | 状态字＋位置，6 字节 |
| 2 | `0x606C:0:32,0x6077:0:16` | 速度＋转矩，6 字节 |

- 多帧开关开启后仅使用 FeedbackPdos 集合，忽略旧单帧字段；关闭后恢复旧配置，列表不会被清空。旧单帧开启多帧时保留原映射，不静默变成 SDO。
- 集合整体必须包含本轴状态字，不要求每帧都含状态字。允许完整描述并核对额外对象（如 0x6061 模式显示），但只解码状态字、位置、速度和转矩；当前映射项长度支持 8/16/32 位，不含 64 位对象。
- TPDO 编号不能重复，实际 COB-ID 不能重复或与本轴目标 RPDO 冲突。对象及字节长度必须与驱动配置一致，绑定不会写入 PDO 映射。
- 跨帧重复映射同一个反馈对象时，采用配置顺序中的第一个来源，不用后到帧覆盖。UI 禁止列排序改变视觉顺序；增删、单元格编辑和清空均触发保存。
- ReadFeedback 只等待本次输出所需的 TPDO，全部帧共用 CommunicationTimeoutMs，不按帧数累计超时，不使用上次调用的数据补齐缺帧，也不静默回退 SDO。
- 被动 TPDO 超时返回 Error，表示本次反馈无效/stale，输出变量不更新；原接收退出后可退避重读，不因取消调度窗口永久隔离整轴。原调用尚未退出时，后续 SDO/写入仍在同一 I/O 门排队，不能绕过；共享 CAN 已失效时仍会拒绝操作。
- 每个 COB-ID 独立检查重复时间戳；最终合并时重新检查所有帧的队列年龄。可用硬件时间戳的跨度也须在 FeedbackMaxAgeMs 内，超过时尝试更新较早帧，无法补齐则超时。时间窗口内仍不代表同一个 SYNC 周期。
- 同步型 TPDO 需要序列先按设备要求发送 SYNC，事件/定时型 TPDO 需要驱动产生新反馈；ReadFeedback 只等待接收，不隐式发送 SYNC 或 RTR，不启动后台循环。ReadState、ReadMode 和状态机轮询仍走 SDO。

BindAxis 设置结构版本升级至 2，自动读取版本 1；其他步骤设置结构不变。回退至旧插件时须同时还原旧序列备份，不能把含多 TPDO 的版本 2 设置直接交给旧插件。

SDO 多次读取不是原子快照。TPDO 检查长度、重复硬件时间戳及共享队列驻留时间。FeedbackMaxAgeMs **只约束进入本插件接收队列后的驻留时间，不能证明硬件采样年龄或驱动内部队列年龄**。硬件时间戳不可用时也无法检测源端重复采样。对严格采样新鲜度的应用必须增加设备周期计数等适配，不能以本方案替代实时反馈。

### 并发规则

同轴同时只允许一个控制流程。后端明确支持独立监控时，序列独立调度的 ReadState、ReadMode、ReadFeedback、ReadDiagnostics 可以在运动步骤等待期间请求硬件数据；多个读取也可以共存。插件不会自动创建监控循环，同一串行序列中排在运动步骤后面的读取仍需等待前一步完成。CANopen 后端已声明支持；未声明能力的后端仍拒绝同轴重叠操作。

逻辑上的并发不代表硬件 I/O 并行：单次轴传输串行执行，等待队列也计入通信超时；监控不会改变控制流程的轮询间隔。原有 CANopen SDO 与新插件共享按适配器串行化事务及按需接收队列，轴 PDO 收发也参与事务协调，读取 SDO 不再直接丢弃其他 COB-ID 的帧。绑定节点后，普通 SDO 客户端访问该节点会被拒绝。

单个读取取消不会直接终止控制流程。被动 TPDO 的缺帧/取消在接收实际退出后可重试；等待期间不允许重入。实际 SDO 事务被中断，或非被动/原生 I/O 已隔离时，通信可能已不可继续，后续控制仍会报错；不是所有“读操作”都能无条件重试。读取失败不会以缓存值冒充成功。SDO 多次读取仍不是原子快照，TPDO 反馈仍受前述队列年龄限制。

不要与原始 CAN_Read、PDO 接收、UDS/XCP、同轴周期发送等操作并发竞争同一接收通道或控制字。硬件适配器原始访问仍可绕过 CANopen 协调层；该层不是完整的全协议总线仲裁器。同步和 NMT 操作也必须在序列中按明确顺序执行。

底层调用超时且尚未完成，或者 SDO 事务中途取消、超时、协议响应无效时，连接会被标记不可继续使用，防止新事务误用迟到响应；需要停止操作并通过 CAN_Close/CAN_Open 创建新连接。正常取消不涉及 SDO 事务的原始接收，在底层调用及时结束后不会禁用连接。

软超时只结束上层等待，不能强制终止原生调用。未结束的轴传输继续占用通道，禁止重入，底层释放延后到调用实际完成；如果底层永不返回，资源也可能无法释放。监控不能绕过被阻塞的物理通道，不保证确定性的响应周期。

## 序列示例

### PP 位置运动

CAN_Open → 配置节点 → BindAxis → SetMode(PP) → Enable → MovePosition → StopMotion（按需）→ Disable → UnbindAxis → CAN_Close。

位置、速度、加减速度使用设备原始单位。PP 可选择相对位置；WaitForTarget=true 等待到位，false 仅等待本次新目标握手完成。

### CSP 序列循环

1. 配置 RPDO/TPDO 及 SYNC，BindAxis，SetMode(CSP)。
2. ReadFeedback 读取当前位置，写入已声明变量 `Locals.ActualPosition`。
3. WriteCspTarget 的首次目标使用当前位置；按照驱动要求提交 SYNC。
4. Enable；其状态轮询使用 SDO。若驱动只在 SYNC 边沿处理控制字，或不支持 SDO 控制字访问，此首期实现不适用，需设备适配。
5. 循环：计算下一目标 → WriteCspTarget → CANopen_SyncSend → ReadFeedback → 检查状态与诊断 → 序列等待。
6. 结束：StopMotion → Disable → UnbindAxis → CAN_Close。

CSV/CST 首个目标必须为零。目标数据仅发送一次，Completed 不代表目标已被同步应用，也不代表物理运动完成。首次目标后，轨迹连续性及速度/加速度边界由序列负责。

等待 10 ms 不代表循环周期就是 10 ms；表达式求值、状态 SDO 读取、PDO 发送和 Windows 调度都会增加耗时与抖动。

## 状态、停止与诊断

- 状态机用掩码识别八种标准状态，未识别值标记 Unknown。
- 不隐式故障复位、不自动从 Quick Stop Active 恢复。
- Enable 从未使能状态进入时清除绑定/上一轮留下的启动与模式选项位；PV/PT 在使能前分别预置零速度/零转矩，防止重新使能恢复旧目标。已经处于运行使能时保持幂等，不覆盖当前目标；非零运动仍须显式执行对应目标步骤。
- SetMode 默认要求退出运行使能；写 0x6060 并确认 0x6061。显式开启 AllowWhileEnabled 后才允许按下述约束在 Operation Enabled 状态切换。
- 非使能态 SetMode 根据当前状态选用 0x0000/0x0006/0x0007 的状态控制位，撤销旧启动选项，不把旧控制字中的运行使能位重新写回；即使模式显示匹配也同步核对驱动状态。
- StopMotion 使用 0x605A 选项 1~8，等待速度 0 且退出 Operation Enabled；设备必须已配置合适的停止参数。Disable 只释放使能，不等于减速到零。
- PV/PT 返回 Completed 仅表示目标下发完成，电机可能继续运行。
- HM 等待旧回零完成位撤销后启动；不能撤销该位的厂商实现需设备适配。
- ReadDiagnostics 可读取 0x603F；硬件状态由 DiagnosticIndex/SubIndex/Bytes 明确指定，异常条件为 `(value & DiagnosticMask) == DiagnosticActiveValue`。掩码为 0 只读取，不做判定。
- 不从标准状态字推断 STO 等厂商硬件状态。不支持诊断对象时明确报错。

功能安全由硬件安全继电器、安全 PLC、驱动 STO 等硬件安全链实现。插件的取消和释放逻辑属于工艺清理，尽力停止运动并释放使能，不替代硬件保障。显式解除绑定会报告清理失败；自动回收只能后台记录结果，不能据此确认物理停轴。

### 显式允许使能态切换

SetMode 的“允许使能态切换”（AllowWhileEnabled）默认关闭，旧设置缺少该字段时也保持关闭。只有使用者核实驱动型号、固件及目标模式确实支持使能态切换后才应开启；此选项不是设备兼容性保证。

- 使用者必须先使轴静止、停止周期目标更新，并完成上一周期 PDO/SYNC。插件不会自动停止运动以满足切换前提，也不会自动释放再恢复使能。
- 切换前检查实际速度为零、状态及已配置硬件诊断，拒绝未撤销的启动、故障复位和 Halt 控制位。按源模式检查 PP 已到位、PV/CSV 速度目标为零、PT/CST 转矩目标为零、CSP 目标等于当前位置等条件。
- 目的模式为 PP/CSP 时预置当前位置，为 PV/CSV 时预置零速度，为 PT/CST 时预置零转矩；HM 不自动启动回零。切换过程中确认模式显示并持续检查使能与静止状态。同模式请求检查状态后直接返回，不重新初始化目标。
- CSP/CSV/CST 仍要求已配置对应 PDO；切换后提交一次初始目标 PDO，不隐式发送 SYNC。后续 PDO/SYNC 继续由序列编排。
- 控制步骤发生错误或取消时，仍执行正常的 best-effort 停止运动与释放使能清理；成功切换才保持 Operation Enabled。

例如，经设备验证后可编排 BindAxis → Enable → SetMode(PV, AllowWhileEnabled=true) → RunVelocity。不要把运行中的直接切换作为此流程的适用场景。现有 StopMotion、Disable 含义不变，本次不新增 Halt 步骤。

## 生命周期与结果

轴使用执行期资源表；对已执行过控制操作的轴，在控制操作取消、控制步骤失败、解除绑定或执行资源回收时进行 best-effort 清理。读取步骤本身不启动运动。会话终止后必须解除再重新绑定，不继续使用失败会话。

### 已使能轴与反馈恢复（1.0.5）

- BindAxis 只读取当前控制字/状态字并核对映射，因此无须先把电机去使能；允许已有运行状态，仅建立本插件的会话和节点占用。不自动退出 QuickStop、清故障、恢复旧目标或发送 SYNC/NMT。不能借此与其他主站同时写控制字；本插件的节点独占不等于能探测全总线的控制归属。
- 纯读取会话关闭时不主动写停止/释能。用户执行控制步骤后即进入本插件的控制管理，仍按原策略清理，包括已使能时幂等返回的 Enable；绑定本身不取得这个清理标记。成功绑定仍在运动的轴，不代表已安全停稳。
- 取消链会把令牌传给节点、共享接收和适配器 Read。NI-XNET 的步骤读取取消退出队列等待，不停止由父 CAN 管理的接收泵；ZLG 轮询在原生接收返回后检查令牌。取消请求不能强行中断一个尚未返回的原生调用。
- FeedbackIsPassiveReceive 默认 false。CANopen 只有使用 TPDO 时声明 true；纯接收超时不会污染 SDO 会话，退出后可重试。无 TPDO 时的 SDO 顺序反馈、对象 SDO 读写及未知 EtherCAT 后端不适用这一放行规则；旧第三方后端保持保守。
- “等待结束时底层调用尚未退出”是超时瞬间的快照，不证明令牌没传递或原生永久卡死。日志另有“等待被动接收退出”和“传输隔离”：前者结束可继续排队事务，后者仍须解除绑定及按下层错误恢复通信。
- MonitorTask 遇到普通 TPDO 缺帧应保留本次无效状态并退避重读，不必每次 Unbind/Bind。若仍执行 Unbind，原控制会话的清理可能成功停止并释能，重新 Bind 不会自动 Enable，后续恢复必须显式编排。
- 若清理确实失败、驱动仍使能，旧轴底层已经释放且共享通信仍有效，则可以重新绑定，再按实际状态明确执行 StopMotion/Disable 或其他控制步骤。禁止未结束 I/O 时另开通道强写控制字；共享 CAN/SDO 已失效时，单独重绑轴不能修复父连接。

### 绑定调用令牌不代表会话生命周期（1.0.4）

绑定调用的取消/超时只约束绑定初始化与注册；绑定成功后，取消该调用令牌不会再关闭跨步骤共享的轴会话。后续轴步骤使用各自令牌，轴资源由显式 UnbindAxis 或平台的 Execution 资源回收释放。修复不关闭父 CAN，也不通过自动重绑恢复运动。

若取消发生在初始化或注册阶段，本次绑定中止并回收自己的新资源；后续控制步骤失败/取消，原有终止及有界清理仍保留。底层 I/O/SDO 已隔离时不能因本次修复绕过隔离。停止与退出的真实宿主路径仍须现场验证。

`AxisSession` 不带令牌的构造入口用于执行资源所有权。旧的显式生命周期令牌重载为兼容保留，仅用于调用方确实持有整个会话生命周期的场景，禁止传入 IStepExecutor 的步骤调用令牌；日志来源称为“显式轴会话生命周期令牌取消”。

### 失败与首次终止诊断（1.0.3）

“轴会话已终止”表示轴资源仍在表中，但本会话已拒绝新的操作；它不是 AxisName 不一致，也不表示当前读取已经发出却没收到响应。ReadFeedback / ReadDiagnostics 是只读操作，单次失败不会直接终止会话。先前控制失败或取消、显式关闭、资源 Dispose 或显式外部会话生命周期令牌取消均可能触发终止。旧版绑定步骤调用方令牌误终止会话的问题已在 1.0.4 修复。

- 首次原因只保存一次：触发步骤类型/名称/地址、终止时间、会话标识和原始异常；后续读取及清理失败不能覆盖它。绑定时记录已解析的轴名、连接及节点，不在后台读取可变的 CurrentStep 来猜测起因。
- 最终 Error 的 Message 给出主因，Detail 包含插件版本、执行阶段、耗时、步骤/通信期限、取消状态和异常链，由 SDK 1.2.8 引擎统一写入日志；在平台展开错误详情查看，不额外重复记录相同最终错误。取消返回 Aborted 时另记 Debug 过程诊断。
- 通信上下文区分排队与底层 I/O，包含对象索引/子索引。反馈模式包含所需、已收、缺失/过期 TPDO、当前等待 ID、重复/过期丢弃计数。排队时后端最近快照可能属于正在占用传输的前一个调用；不要把它当成本次已发送的请求。
- 若旧版日志来源是“绑定步骤调用方令牌取消”，说明步骤令牌的取消错误地传播到了共享会话，需更新 1.0.4；这不证明宿主具体为何取消该令牌。步骤总超时、会话/后端取消分别诊断，不将全部 OperationCanceledException 当作超时。
- 反复出现终止提示时，先查同一会话标识对应的“首次终止”和首个错误详情，再停止相关控制、确认安全后解除绑定及恢复通信。序列自己的 staleCount 只能表示连续失败次数，不能代替首故障证据。
- 不自动恢复失效会话，也不为日志新增硬件读写、CAN 包装或后台接收器。存在未退出 I/O 或已中断 SDO 的隔离保护保持不变。

### 清理与释放

- 同一会话的清理只启动一次，取消回调和同步 `Dispose()` 仅发起后台清理，不同步等待通信、原生释放或日志。控制步骤及时返回原始错误或取消结果，不额外等待另一轮清理。同名轴的绑定与解绑在本插件内串行化，排队受步骤期限和取消约束，避免旧解绑误删新会话；不持有父 CAN 生命周期。
- `UnbindAxis` / `CloseAsync()` / `DisposeAsync()` 等待清理结果。统一等待期限为 2000 ms，覆盖活动操作退出、停止运动、释放使能及底层释放，不随单次通信超时累加；步骤总超时或调用方取消可以进一步缩短此期限。此期限是软件等待上限，不是实时停轴保证。
- 显式解除绑定只有清理及释放成功才返回 Completed。通信失败、截止时间到达或底层释放失败返回 Error，用户取消返回 Aborted；无论结果如何都移除终止会话，后续资源表回收不再重复等待。
- 已超时或取消后不再排队新的清理命令。尚未返回的轴传输调用继续保留占用，实际退出后才释放一次；`AxisSession.Released` 可区分本轴传输实例释放完成与上层停止等待，不代表父 CAN 的原生句柄已关闭。CiA402 只能观察所调用的后端方法，CAN 驱动内部原生调用的隔离仍由 CAN 插件负责。后端永不返回时占用仍可能无法释放，不通过重入或强行释放掩盖问题。
- 清理日志通过有界队列异步写入，记录阶段耗时及底层释放结果；日志回调阻塞或抛错不会拖住清理。若宿主日志持续阻塞，最多保留一个工作线程及 16 条待处理日志，后续诊断可能丢弃。
- CiA402 只管理自身轴会话和节点占用，不关闭、重开或包装父 CAN 连接。正常序列仍应先 `StopMotion` / `Disable`，再等待 `UnbindAxis` 完成，最后执行 `CAN_Close`；若外部已经关闭 CAN，停轴写入会明确失败，不接管连接。自动资源回收不能替代这个显式顺序。

正常 Completed；参数、通信、设备状态或超时问题 Error；用户取消 Aborted。只读诊断成功而设备报告故障时，可返回 Completed 并输出故障信息，由序列决定测试结论。

## 变量与编辑器

输入表达式结果按目标类型严格校验，不接受数字字符串代替数值。所有输出都必须为用户已声明的完整路径，如 `Locals.ActualPosition`，留空不写。数值输出可写入现有数值变量并进行范围检查；布尔和文本输出类型必须匹配。不自动创建变量，不拼接输出路径。

每个步骤采用独立 EditorPlugin、强类型 ViewModel 和 XAML 视图，显式声明字段绑定与校验，支持表达式控件、防抖保存和生命周期前置校验。插件入口直接继承 StepPluginBase，设置只保留 SDK 要求的序列化、表达式及变量路径标记，不使用自定义 Field 元数据或反射生成界面。动态分支、子序列的静态前置判断仅作警告，运行时仍严格检查实际会话和驱动状态。

## EtherCAT 扩展

主站插件将 `ICia402EtherCatFactory` 注册到 `CiA402.EtherCAT.Factory`。工厂接收连接名、从站地址和绑定配置，返回独占轴访问的 `ICia402AxisTransport`。适配器须协调 CoE/过程映像，保证取消、I/O 有界和数据有效性，不关闭共享主站。

接口的 SupportsConcurrentMonitoring 默认 false；后端只有确认能在控制流程的 I/O 间隙提供独立硬件读取时才可声明 true。声明后依然由包装层串行调用后端，并不要求或允许同一轴底层事务重入。FeedbackIsPassiveReceive 也默认 false：只有 ReadFeedback 无协议请求且退出后能安全重试（或下层仍可靠隔离）才可声明 true，不能以此清除真实原生/协议故障。RequireCyclicMode 只能检查不可变配置，不能执行阻塞 I/O。

未来主站即使提供实时通信，也不改变本版本测试序列目标更新是非实时的事实。

## 构建与验证

执行/UI 工程输出到工作区 `artifacts/<Configuration>/Plugins/CiA402/`，不自动部署主程序。CAN 项目引用按已有工程配置构建；发布时需保持 CAN 依赖与本插件使用一致版本，不在同一运行环境加载不同版本副本。

无硬件 xUnit 测试项目位于 Cia402Plugin.Tests，验证状态机、协议编码、模式操作、取消与插件契约。在 Windows 上运行 `dotnet test CiA402/Cia402Plugin.Tests/Cia402Plugin.Tests.csproj`，也可在 Visual Studio Test Explorer 中发现、单独运行和调试测试。WPF 编辑器用例使用 StaFact；为避免时序测试互相干扰，测试集合不并行执行，用例内部的并发场景仍保留。

原有 114 个用例包含七种源模式与七种目的模式的 49 个组合、独立编辑器加载、全部字段绑定及保存回调验证。1.0.1 的 18 项生命周期回归验证同步回收、统一期限、日志阻塞、延后释放和不关闭共享 CAN；1.0.2 新增 37 项，共 169 个用例，覆盖多 TPDO 乱序、缺帧、时间窗口、重复时间戳、映射及 COB-ID 冲突、旧版本迁移、真实 WPF 单元格提交保存、同名轴绑定/解绑串行与排队取消，以及使能与模式切换保护。1.0.3 新增 13 项首故障及错误上下文回归，共 182 项，包含取消分类、隔离原始原因、解绑后快照、多轴隔离和日志异常。1.0.4 再新增 4 项绑定生命周期回归，全量 186 项：绑定返回后取消原令牌仍可读取、初始化取消、注册阶段取消回撤、后续控制自身取消；通过模拟资源移除核对仅本轴释放。

1.0.5 新增 18 项恢复与 UI 回归，全量 204/204：纯接收取消的两种退出异常、未退出不重入/不提前释放、非被动事务保守隔离、TPDO 能力声明、缺 TPDO 后诊断及下次反馈、失败输出不更新且显式 PV 可继续、原生不退出时保留共享 CAN 隔离、已使能/QuickStop/故障态只读绑定、只读解绑无控制写入、清理失败后重绑及显式 PV、绑定状态日志异常，以及 WPF 提示布局。测试结果不代表真实设备接受这些模式转换或停轴时序。

发布流程只构建插件执行层和 UI 层，测试产物不进入插件包。步骤提取器优先扫描与插件目录同名的主程序集，避免私有 CAN 依赖被重复列入 CiA402 步骤清单。实际设备的 PDO/SYNC、停止策略和非实时周期容忍度仍需现场验证。
